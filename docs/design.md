# 校园失物招领 Web 设计

本设计依据 requirement.md、../homework3/work3.md 和用户于 2026-10-08 确认的整体计划。交付面向 Chrome 的本机演示应用，保留蓝白卡片风格，适配电脑与窄屏。Figma 画布读取失败，已查看报告中的页面截图作为视觉依据。

根据用户补充要求，页面使用原有“校园失物招领”名称，去除自行增加的品牌、宣传横幅、统计栏、装饰性小字和提示侧栏。电脑端列表采用双列紧凑卡片，表单字段分两列，详情与联系方式分栏；窄屏改为单列。保留原型的底部导航、类型切换、状态标签与直接操作，不追求手机原型的像素级还原。

## 范围与架构

- 原生 HTML/CSS/JavaScript；单个 index.html 入口，hash 导航；普通 script 顺序加载，不使用 CDN、ES module、构建工具或本地 JSON fetch。
- 页面包含首页、搜索、发布、成功、详情、我的发布及编辑。
- core.js 提供纯业务逻辑；storage.js 管理 localStorage；app.js 管理路由及交互；views.js 渲染页面；ui.js 提供图标及安全文本工具。
- 所有视图使用同一份记录。初始化写入少量明确标注的示例记录，示例发布者与当前浏览器身份不同。
- 本地匿名 ownerId 区分自己的记录；不是账号认证，不跨浏览器或设备同步。

## 数据与行为

Post 包含 id、type(lost/found)、title、category、location、occurredAt(本地日期时间)、description、contact、ownerId、status(open/resolved)、createdAt、updatedAt，以及可选 image。

可选图片支持 JPG、PNG、WebP，原文件不超过 10 MB、2400 万像素；images.js 在浏览器内等比缩小（最长边不超过 1200px）并压缩为 JPEG，序列化内容最多 360000 字符。类别决定默认 SVG 插画，照片优先用于卡片与详情。编辑可以保留、更换或移除照片，单独修改照片也触发未保存提醒。处理中的旧任务不能写入新页面。存储结构仍为 v1，兼容原有不含 image 的记录。

用户允许为了简洁暂不添加真实登录、共享数据库及认领申请；当前继续采用已确定的本机方案，不创建后端或虚构账号登录。

名称、类别、地点、时间、描述、联系方式必填；文本去除首尾空格并限制合理长度；允许电话、QQ、微信等文字联系方式；禁止非法或未来时间。

寻物 open 显示“寻找中”，resolved 显示“已找到”；招领 open 显示“待认领”，resolved 显示“已归还”。只有 ownerId 相同的记录可编辑或完成，完成为幂等单向操作，编辑不重置状态。

关键词按标题、地点、描述进行不区分大小写的子串匹配；类别、地点、类型条件取交集；默认按创建时间倒序。空关键词展示满足其他条件的全部记录。完成信息仍可浏览，有明显状态标签。

## 运行及异常

存储先成功再切换应用状态。读写失败、非法存储内容、无结果、记录不存在、未保存离开均有明确提示；损坏数据不静默覆盖。剪贴板写入成功后才提示成功，失败时展示可选中文本。用户文本按文本渲染，避免执行 HTML。

file:// 下 localStorage 需在 Chrome 实测；README 说明同一浏览器配置和文件路径的边界。图片仅在浏览器内处理；无登录、服务器、聊天、地图或后台管理。

## 验收

至少 12 个 Node 内置测试，覆盖校验、查询、身份、状态和存储异常。使用真实 Chrome 的 file:// 入口验证发布→详情→我的发布→完成状态→刷新；检验编辑、导航、窄屏及离线运行。README、测试报告、PSP、博客草稿和 GitHub 协作说明随项目交付；不虚构人工分工成果、试用反馈或远程提交。
